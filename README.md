# กินได้ไหม? — เว็บแอปอาหารสุนัขและแมว

เว็บแอปที่ช่วยเจ้าของสุนัขและแมวเช็กว่าอาหารของคนชนิดใดที่น้องกินได้ ติดตั้งบนหน้าจอโฮมของมือถือได้ (PWA) และเปิดได้แม้ไม่มีอินเทอร์เน็ต
เป็นไฟล์ธรรมดาทั้งหมด ไม่ต้อง build จึงอัปโหลดขึ้น GitHub Pages ได้ทันที

## ไฟล์แต่ละไฟล์คืออะไร

| ไฟล์ | หน้าที่ | แก้เองได้ไหม |
|---|---|---|
| `js/config.js` | **การตั้งค่าทั้งหมด** ได้แก่ ผู้ตรวจทาน เบอร์โรงพยาบาลสัตว์ Google Form และปุ่มยอดนิยม | **ได้ ไฟล์หลักที่ต้องแก้** |
| `data/foods.json` | ข้อมูลอาหารทั้งหมด (58 รายการ) | ได้ (ระวังรูปแบบ JSON) |
| `sw.js` | ทำให้แอปใช้ได้ตอนออฟไลน์ มีเลข `CACHE_VERSION` | แก้เฉพาะเลขเวอร์ชัน |
| `privacy.html` | นโยบายความเป็นส่วนตัว | ได้ (ต้องกรอกช่อง [ ]) |
| `terms.html` | ข้อตกลงการใช้งานและข้อจำกัดความรับผิด | ได้ (ต้องกรอกช่อง [ ]) |
| `index.html` | หน้าแอปหลัก | ไม่จำเป็น |
| `css/app.css` | สีและรูปแบบหน้าจอ | ไม่จำเป็น |
| `js/app.js` | โค้ดการทำงานของแอป | ไม่จำเป็น |
| `js/legal.js` | ใส่ชื่อสัตวแพทย์จาก config.js ลงในหน้าข้อตกลงการใช้งาน | ไม่จำเป็น |
| `manifest.webmanifest` | ชื่อแอปและไอคอนเวลาติดตั้งบนมือถือ | ไม่จำเป็น |
| `icons/` | ไอคอนแอป (192, 512, maskable, apple-touch-icon, favicon) และภาพตัวอย่างลิงก์ `og.png` | ไม่จำเป็น |
| `404.html` | หน้าที่แสดงเมื่อเปิดลิงก์ผิด | ไม่จำเป็น |
| `.nojekyll` | ไฟล์ว่าง บอก GitHub Pages ไม่ต้องแปลงไฟล์ | ห้ามลบ |

## วิธีแก้ `js/config.js`

เปิดไฟล์ด้วยโปรแกรมแก้ข้อความ (หรือกดรูปดินสอในหน้า GitHub) ทุกส่วนมีคำอธิบายภาษาไทยกำกับไว้
ข้อความต้องอยู่ใน `'...'` และระหว่างรายการต้องมี `,` คั่น

1. **REVIEW** เมื่อสัตวแพทย์ตรวจทานแล้ว ให้ใส่ชื่อและวันที่ เช่น
   `REVIEW: { reviewer: 'สมใจ ใจดี', date: '1 พ.ย. 2569' },`
   ป้าย "ฉบับร่าง" จะหายไปทุกหน้า และชื่อจะไปแสดงในหน้าข้อตกลงการใช้งานด้วย
2. **VET_CONTACTS** ใส่โรงพยาบาลสัตว์ 24 ชม. เฉพาะที่โทรตรวจสอบแล้ว รูปแบบ
   `{ name: '...', province: 'สงขลา', phone: '07x xxx xxxx', hours: '24 ชม.' }`
   ถ้าว่าง แอปจะแสดงคำแนะนำให้โทรหาโรงพยาบาลใกล้บ้าน (แอปจะไม่แต่งเบอร์ขึ้นเอง)
3. **FEEDBACK** (Google Forms ไม่บังคับ)
   - สร้าง Google Form ที่มีคำถามแบบ **"คำตอบสั้น"** 9 ข้อ (ห้ามตั้งเป็น "จำเป็น") ได้แก่ ชนิดข้อมูล, อาหาร, สัตว์, มีประโยชน์ไหม, ใช้งานง่าย, เชื่อถือ, จะกลับมาใช้ไหม, ความคิดเห็น, คำค้น
     ถ้าใช้คำถามแบบตัวเลือก ค่าที่แอปส่งไปต้องตรงกับตัวเลือกทุกตัวอักษร จึงแนะนำให้ใช้ "คำตอบสั้น"
   - `formUrl` = ลิงก์ฟอร์มที่ลงท้ายด้วย `/viewform`
   - `postUrl` = ลิงก์เดียวกันแต่เปลี่ยน `/viewform` เป็น `/formResponse` (ถ้าใส่ แอปจะส่งได้ทันทีโดยไม่ต้องเปิดฟอร์ม)
   - `fields` = รหัส `entry.xxxxx` ของแต่ละคำถาม วิธีหา: ในฟอร์ม กด ⋮ > "รับลิงก์ที่กรอกไว้ล่วงหน้า" กรอกทุกช่อง > "รับลิงก์" > วางลิงก์ แล้วดูเลขหลัง `entry.`
   - ถ้าไม่ใส่อะไรเลย แอปจะ**ไม่ส่งข้อมูลออกจากเครื่อง** หน้าส่งความคิดเห็นจะให้ผู้ใช้คัดลอกข้อความแทน
   - ถ้าใส่แค่ `formUrl` แอปจะเปิดฟอร์มที่กรอกคำตอบไว้ให้ ผู้ใช้กดส่งเองในฟอร์ม
4. **POPULAR_IDS** รายการปุ่ม "ค้นหายอดนิยม" ใช้รหัส `id` จาก `data/foods.json`

## วิธีอัปเดตข้อมูลอาหาร (`data/foods.json`)

1. แก้หรือแทนที่ไฟล์ `data/foods.json` ทั้งไฟล์ (รูปแบบเหมือนเดิม: `id`, `name_th`, `aliases`, `category`, `dog`, `cat`, `if_eaten_th`, `serving_th`, `sources`)
2. ตรวจว่า JSON ถูกต้อง เช่น วางใน jsonlint.com หรือรัน `python3 -m json.tool data/foods.json`
   ถ้า JSON ผิด แอปจะแสดง "โหลดข้อมูลอาหารไม่สำเร็จ"
3. **เปิด `sw.js` แล้วเพิ่มเลข `CACHE_VERSION`** เช่น `'v1'` → `'v2'`

> ทุกครั้งที่แก้ไฟล์ใดก็ตาม (รวมถึง config.js) ให้เพิ่มเลข `CACHE_VERSION` ใน `sw.js`
> ผู้ใช้เดิมจะเห็นแถบ "มีเวอร์ชันใหม่ — แตะเพื่ออัปเดต"

## ทดสอบบนเครื่องตัวเอง

```
cd site
python3 -m http.server 8000
```
แล้วเปิด http://localhost:8000 (ต้องเปิดผ่าน http ไม่ใช่ดับเบิลคลิกไฟล์ เพราะแอปต้องโหลด `data/foods.json`)
ระบบออฟไลน์ทำงานเฉพาะบน `https://` หรือ `localhost`

## ขึ้นเว็บด้วย GitHub Pages

1. สร้าง repository ใหม่ อัปโหลดไฟล์ทั้งหมดในโฟลเดอร์ `site` ไว้ที่ระดับบนสุดของ repository
2. Settings > Pages > Source: "Deploy from a branch" > เลือก `main` และ `/ (root)`
3. รอสักครู่ เว็บจะอยู่ที่ `https://ชื่อผู้ใช้.github.io/ชื่อrepository/`
4. หลังได้ที่อยู่เว็บจริง ให้แก้ `og:image` ใน `index.html` เป็นลิงก์เต็ม เช่น `https://ชื่อผู้ใช้.github.io/ชื่อrepository/icons/og.png` เพื่อให้ภาพตัวอย่างขึ้นเมื่อแชร์ใน LINE/Facebook

## รายการตรวจก่อนเปิดให้ใช้จริง

- [ ] สัตวแพทย์ตรวจทานข้อมูลใน `data/foods.json` ครบทุกรายการ และลงชื่อรับรอง
- [ ] ใส่ชื่อและวันที่ใน `REVIEW` ของ `js/config.js` แล้ว (ป้าย "ฉบับร่าง" หายไป)
- [ ] `VET_CONTACTS` ทุกเบอร์โทรตรวจสอบแล้วว่าถูกต้องและเปิด 24 ชม. จริง
- [ ] กรอกช่อง [ ] ใน `privacy.html` และ `terms.html` ครบ (ผู้จัดทำ อีเมลติดต่อ ระยะเวลาเก็บข้อมูล วันที่มีผล ชื่อสัตวแพทย์)
- [ ] ฝ่ายกฎหมายและเจ้าหน้าที่คุ้มครองข้อมูลส่วนบุคคล (DPO) ของมหาวิทยาลัยตรวจนโยบายความเป็นส่วนตัวและข้อตกลงการใช้งานแล้ว
- [ ] เชื่อม Google Form แล้ว และทดลองส่ง: แบบสอบถาม, ปุ่ม "มีประโยชน์/ยังไม่ชัด", ค้นหาคำที่ไม่มีในระบบ, ปุ่ม "ขอให้เพิ่มเมนูนี้" ข้อมูลขึ้นใน Google Sheets ถูกช่อง
- [ ] ทดลองเปิดในโหมดไม่ระบุตัวตน: ต้องเห็นประกาศเรื่องข้อมูลก่อนเริ่มใช้งาน
- [ ] ทดสอบบน Android (Chrome): ติดตั้งแอป เปิดแบบออฟไลน์ (เปิดโหมดเครื่องบิน) แล้วค้นหา "องุ่น" ได้
- [ ] ทดสอบบน iPhone (Safari): "เพิ่มไปยังหน้าจอโฮม" เปิดได้และค้นหาได้
- [ ] เพิ่มเลข `CACHE_VERSION` ใน `sw.js` หลังแก้ไขครั้งสุดท้าย
- [ ] (ไม่บังคับ) ตั้งโดเมนของตัวเองที่ Settings > Pages > Custom domain

## ข้อควรรู้

- Google Forms ไม่ส่งผลกลับมาให้แอปอ่าน แอปจึงรู้แค่ว่าส่งออกจากเครื่องแล้ว ไม่รู้ว่า Google รับสำเร็จหรือไม่ ควรตรวจใน Google Sheets เป็นระยะ
- การให้คะแนนหรือคำค้นที่ส่งตอนออฟไลน์จะไม่ถูกส่งซ้ำภายหลัง (มีสำเนาเก็บในเครื่องผู้ใช้ และแนบไปกับข้อความสรุปของแบบสอบถาม)
- ผู้ใช้ปิดการส่งข้อมูลอัตโนมัติได้ที่หน้า "เกี่ยวกับข้อมูล" > "ไม่ส่งข้อมูลการใช้งาน"
- ถ้าใช้ GitHub Pages แบบ `ชื่อผู้ใช้.github.io` (ไม่มีชื่อ repository ต่อท้าย) ปุ่ม "กลับหน้าแรก" ในหน้า 404 อาจพาไปผิดที่ ให้แก้สคริปต์ท้าย `404.html` เป็น `a.href = '/'`
