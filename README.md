# กินได้ไหม? — เว็บแอปอาหารสุนัขและแมว

เว็บแอปที่ช่วยเจ้าของสุนัขและแมวเช็กว่าอาหารของคนชนิดใดที่น้องกินได้ ติดตั้งบนหน้าจอโฮมของมือถือได้ (PWA) และเปิดได้แม้ไม่มีอินเทอร์เน็ต
เป็นไฟล์ธรรมดาทั้งหมด ไม่ต้อง build จึงอัปโหลดขึ้น GitHub Pages ได้ทันที

## ไฟล์แต่ละไฟล์คืออะไร

| ไฟล์ | หน้าที่ | แก้เองได้ไหม |
|---|---|---|
| `js/config.js` | **การตั้งค่าทั้งหมด** ได้แก่ ผู้ตรวจทาน เบอร์โรงพยาบาลสัตว์ Google Form และปุ่มยอดนิยม | **ได้ ไฟล์หลักที่ต้องแก้** |
| `data/foods.json` | ข้อมูลอาหารทั้งหมด (58 รายการ) | ได้ (ระวังรูปแบบ JSON) |
| `sw.js` | ทำให้แอปใช้ได้ตอนออฟไลน์ มีเลข `CACHE_VERSION` | แก้เฉพาะเลขเวอร์ชัน |
| `privacy.html` / `privacy-en.html` | นโยบายความเป็นส่วนตัว (ไทย / อังกฤษ) | ได้ (ต้องกรอกช่อง [ ] ทั้งสองภาษา) |
| `terms.html` / `terms-en.html` | ข้อตกลงการใช้งานและข้อจำกัดความรับผิด (ไทย / อังกฤษ) | ได้ (ต้องกรอกช่อง [ ] ทั้งสองภาษา) |
| `index.html` | หน้าแอปหลัก | ไม่จำเป็น |
| `css/app.css` | สีและรูปแบบหน้าจอ | ไม่จำเป็น |
| `js/i18n.js` | ข้อความทุกข้อความในแอป ภาษาไทยและอังกฤษ | ได้ (แก้คำในแอป) |
| `js/app.js` | โค้ดการทำงานของแอป | ไม่จำเป็น |
| `js/legal.js` | ใส่ชื่อสัตวแพทย์จาก config.js ลงในหน้าข้อตกลงการใช้งาน | ไม่จำเป็น |
| `manifest.webmanifest` | ชื่อแอปและไอคอนเวลาติดตั้งบนมือถือ | ไม่จำเป็น |
| `icons/` | ไอคอนแอป (192, 512, maskable, apple-touch-icon, favicon) และภาพตัวอย่างลิงก์ `og.png` | ไม่จำเป็น |
| `404.html` | หน้าที่แสดงเมื่อเปิดลิงก์ผิด | ไม่จำเป็น |
| `.nojekyll` | ไฟล์ว่าง บอก GitHub Pages ไม่ต้องแปลงไฟล์ | ห้ามลบ |

## วิธีแก้ `js/config.js`

เปิดไฟล์ด้วยโปรแกรมแก้ข้อความ (หรือกดรูปดินสอในหน้า GitHub) ทุกส่วนมีคำอธิบายภาษาไทยกำกับไว้
ข้อความต้องอยู่ใน `'...'` และระหว่างรายการต้องมี `,` คั่น

1. **REVIEW** เมื่อสัตวแพทย์ตรวจทานแล้ว ให้ใส่ชื่อและวันที่ เช่น
   `REVIEW: { reviewer: 'สมใจ ใจดี', date: '1 พ.ย. 2569' },`
   ป้าย "ฉบับร่าง" จะหายไปทุกหน้า และชื่อจะไปแสดงในหน้าข้อตกลงการใช้งานด้วย
2. **VET_CONTACTS** ใส่โรงพยาบาลสัตว์ 24 ชม. เฉพาะที่โทรตรวจสอบแล้ว รูปแบบ
   `{ name: '...', province: 'สงขลา', phone: '07x xxx xxxx', hours: '24 ชม.' }`
   ถ้าว่าง แอปจะแสดงคำแนะนำให้โทรหาโรงพยาบาลใกล้บ้าน (แอปจะไม่แต่งเบอร์ขึ้นเอง)
3. **FEEDBACK** (Google Forms ไม่บังคับ)
   - สร้าง Google Form ที่มีคำถามแบบ **"คำตอบสั้น"** 9 ข้อ (ห้ามตั้งเป็น "จำเป็น") ได้แก่ ชนิดข้อมูล, อาหาร, สัตว์, มีประโยชน์ไหม, ใช้งานง่าย, เชื่อถือ, จะกลับมาใช้ไหม, ความคิดเห็น, คำค้น
     ถ้าใช้คำถามแบบตัวเลือก ค่าที่แอปส่งไปต้องตรงกับตัวเลือกทุกตัวอักษร จึงแนะนำให้ใช้ "คำตอบสั้น"
   - `formUrl` = ลิงก์ฟอร์มที่ลงท้ายด้วย `/viewform`
   - `postUrl` = ลิงก์เดียวกันแต่เปลี่ยน `/viewform` เป็น `/formResponse` (ถ้าใส่ แอปจะส่งได้ทันทีโดยไม่ต้องเปิดฟอร์ม)
   - `fields` = รหัส `entry.xxxxx` ของแต่ละคำถาม วิธีหา: ในฟอร์ม กด ⋮ > "รับลิงก์ที่กรอกไว้ล่วงหน้า" กรอกทุกช่อง > "รับลิงก์" > วางลิงก์ แล้วดูเลขหลัง `entry.`
   - ถ้าไม่ใส่อะไรเลย แอปจะ**ไม่ส่งข้อมูลออกจากเครื่อง** หน้าส่งความคิดเห็นจะให้ผู้ใช้คัดลอกข้อความแทน
   - ถ้าใส่แค่ `formUrl` แอปจะเปิดฟอร์มที่กรอกคำตอบไว้ให้ ผู้ใช้กดส่งเองในฟอร์ม
4. **POPULAR_IDS** รายการปุ่ม "ค้นหายอดนิยม" ใช้รหัส `id` จาก `data/foods.json`

## ภาษาไทย / English (i18n)

แอปมีปุ่ม **ไทย | EN** ที่หัวหน้าจอ (มือถือ) และแถบเมนูซ้าย (คอมพิวเตอร์) ภาษาที่เลือกจำไว้ในเครื่อง (`kdm-lang`) ถ้ายังไม่เคยเลือก แอปดูจากภาษาของเบราว์เซอร์ (ขึ้นต้น `th` = ไทย นอกนั้น = อังกฤษ)

**แก้หรือเพิ่มข้อความ** ทุกข้อความอยู่ใน `js/i18n.js` แบ่งเป็น `th: { ... }` และ `en: { ... }` ใช้ "คีย์" เดียวกัน เช่น
```
'fav.h': 'รายการที่บันทึก',      // ใน th
'fav.h': 'Saved items',          // ใน en
```
- `{name}`, `{n}` คือค่าที่แอปเติมให้ ห้ามแปลหรือลบ
- คีย์ที่ลงท้าย `_one` ใช้กับภาษาอังกฤษเมื่อ `{n}` = 1 เช่น `'res.found_one': '1 result'`
- ถ้าคีย์ไม่มีใน `en` แอปจะแสดงภาษาไทยแทน
- ข้อความใน `index.html` ผูกด้วย `data-i18n="คีย์"` (ข้อความ), `data-i18n-html="คีย์"` (มีแท็ก เช่น ลิงก์) หรือ `data-i18n-attr="placeholder:คีย์;aria-label:คีย์2"` (แอตทริบิวต์) ส่วนใน `js/app.js` ใช้ `t('คีย์', {n: 3})`
- ข้อความที่ส่งไป Google Forms ยังเป็นภาษาไทยเสมอ เพื่อให้ชีตคำตอบเป็นรูปแบบเดียว

**ข้อมูลอาหารภาษาอังกฤษ** (ไม่บังคับ) ในแต่ละรายการของ `data/foods.json` ใส่ได้: `name_en`, `aliases_en` (รายการคำค้น), `dog.note_en`, `cat.note_en`, `if_eaten_en`, `serving_en` (แยกสุนัข/แมวแบบ `"Dog: … | Cat: …"` เหมือน `"สุนัข: … | แมว: …"`) โหมดอังกฤษจะแสดงช่องเหล่านี้ ถ้าไม่มีจะแสดงภาษาไทย การค้นหาหาได้ทั้งชื่อไทยและอังกฤษในทั้งสองโหมด

**ปุ่มใน `js/config.js`** ใส่ `title_en`, `sub_en`, `query_en` (บริการใกล้ฉัน / หาบ้าน), `name_en`, `sub_en` (องค์กร) และ `name_en`, `province_en`, `hours_en` (โรงพยาบาลสัตว์) ได้

**หน้าเอกสาร** แก้ทั้ง `privacy.html` + `privacy-en.html` และ `terms.html` + `terms-en.html` ให้ตรงกันเสมอ หลังแก้ไฟล์ใดก็ตาม เพิ่ม `CACHE_VERSION` ใน `sw.js`

## หน้าจอมือถือ แท็บเล็ต และคอมพิวเตอร์

- มือถือ (กว้างน้อยกว่า 720px): คอลัมน์เดียว เมนูแถบล่าง
- แท็บเล็ต (720–1023px): เนื้อหากว้างขึ้น เมนูแถบล่างอยู่กลาง รายการบางส่วนเป็น 2 คอลัมน์
- คอมพิวเตอร์ (1024px ขึ้นไป): เมนูด้านซ้าย (มีปุ่มฉุกเฉินสีแดงและปุ่มภาษา) เนื้อหากว้างสุด ~1100px หน้าผลลัพธ์ สมุดสุขภาพ และฉุกเฉินแบ่งเป็น 2 คอลัมน์

## วิธีอัปเดตข้อมูลอาหาร (`data/foods.json`)

1. แก้หรือแทนที่ไฟล์ `data/foods.json` ทั้งไฟล์ (รูปแบบเหมือนเดิม: `id`, `name_th`, `aliases`, `category`, `dog`, `cat`, `if_eaten_th`, `serving_th`, `sources`)
2. ตรวจว่า JSON ถูกต้อง เช่น วางใน jsonlint.com หรือรัน `python3 -m json.tool data/foods.json`
   ถ้า JSON ผิด แอปจะแสดง "โหลดข้อมูลอาหารไม่สำเร็จ"
3. **เปิด `sw.js` แล้วเพิ่มเลข `CACHE_VERSION`** เช่น `'v1'` → `'v2'`

> ทุกครั้งที่แก้ไฟล์ใดก็ตาม (รวมถึง config.js) ให้เพิ่มเลข `CACHE_VERSION` ใน `sw.js`
> ผู้ใช้เดิมจะเห็นแถบ "มีเวอร์ชันใหม่ — แตะเพื่ออัปเดต"

## ทดสอบบนเครื่องตัวเอง

```
cd site
python3 -m http.server 8000
```
แล้วเปิด http://localhost:8000 (ต้องเปิดผ่าน http ไม่ใช่ดับเบิลคลิกไฟล์ เพราะแอปต้องโหลด `data/foods.json`)
ระบบออฟไลน์ทำงานเฉพาะบน `https://` หรือ `localhost`

## ขึ้นเว็บด้วย GitHub Pages

1. สร้าง repository ใหม่ อัปโหลดไฟล์ทั้งหมดในโฟลเดอร์ `site` ไว้ที่ระดับบนสุดของ repository
2. Settings > Pages > Source: "Deploy from a branch" > เลือก `main` และ `/ (root)`
3. รอสักครู่ เว็บจะอยู่ที่ `https://ชื่อผู้ใช้.github.io/ชื่อrepository/`
4. หลังได้ที่อยู่เว็บจริง ให้แก้ `og:image` ใน `index.html` เป็นลิงก์เต็ม เช่น `https://ชื่อผู้ใช้.github.io/ชื่อrepository/icons/og.png` เพื่อให้ภาพตัวอย่างขึ้นเมื่อแชร์ใน LINE/Facebook

## ตั้งค่าโพสต์หาบ้าน (หน้า "หาบ้านหมาแมว")

ระบบนี้ใช้ Google Form ให้คนโพสต์ และใช้ Google Sheets เป็นที่เก็บข้อมูล โพสต์จะขึ้นแอปเมื่อผู้ดูแลติ๊กอนุมัติแล้วเท่านั้น

1. **สร้างฟอร์ม** ชื่อ "โพสต์หาบ้านให้น้อง" แล้วเพิ่มคำถามตามลำดับนี้
   ชื่อน้อง (คำตอบสั้น), ชนิด (ตัวเลือก: น้องหมา / น้องแมว), เพศ (ตัวเลือก: ผู้ / เมีย / ไม่ทราบ), อายุโดยประมาณ (คำตอบสั้น), จังหวัด (คำตอบสั้น), อำเภอ (คำตอบสั้น), ทำหมันแล้วหรือยัง (ตัวเลือก: ทำแล้ว / ยังไม่ทำ / ไม่ทราบ), วัคซีน (คำตอบสั้น), นิสัยและรายละเอียด (ย่อหน้า), รูปน้อง (อัปโหลดไฟล์ จำกัด 1 รูป ชนิดรูปภาพ), LINE ID สำหรับให้ผู้สนใจติดต่อ (คำตอบสั้น), การยินยอม (ช่องทำเครื่องหมาย: "ยินยอมให้แสดงข้อมูลน้องและ LINE ID ในแอป และยืนยันว่าให้รับเลี้ยงฟรี ไม่ใช่การขาย") ตั้งเป็นบังคับตอบ
2. **เชื่อมกับชีต** ที่แท็บ "คำตอบ" แล้วเพิ่ม 2 คอลัมน์ต่อท้ายเองในชีตคำตอบ: `อนุมัติ` (แทรก → ช่องทำเครื่องหมาย) และ `สถานะ` (พิมพ์ "ได้บ้านแล้ว" เมื่อน้องได้บ้าน)
3. **เปิดให้ดูรูปได้** ใน Google Drive จะมีโฟลเดอร์ของไฟล์ที่อัปโหลดจากฟอร์ม ตั้งค่าแชร์โฟลเดอร์นั้นเป็น "ทุกคนที่มีลิงก์ดูได้"
4. **สร้างแท็บ `public`** แล้ววางสูตรนี้ในช่อง A1 (ถ้าชื่อแท็บคำตอบต่างจากนี้ ให้แก้ชื่อในสูตร และถ้าลำดับคอลัมน์ต่างไป ให้แก้ตัวอักษรคอลัมน์ให้ตรง) โดย A = ประทับเวลา, B–L = คำถามข้อ 1–11, M = การยินยอม, N = อนุมัติ, O = สถานะ
   ```
   ={"posted_at","name","species","sex","age","province","district","sterilized","vaccinated","details","photo","line_id","status"; QUERY('การตอบกลับแบบฟอร์ม 1'!A2:O, "select A,B,C,D,E,F,G,H,I,J,K,L,O where N = TRUE", 0)}
   ```
5. **เผยแพร่เฉพาะแท็บ public** เมนู ไฟล์ → แชร์ → เผยแพร่ไปยังเว็บ → เลือกแท็บ `public` และรูปแบบ "ค่าที่คั่นด้วยจุลภาค (.csv)" → เผยแพร่ แล้วคัดลอกลิงก์ (แท็บคำตอบที่มีข้อมูลยังไม่อนุมัติจะไม่ถูกเผยแพร่)
6. **ใส่ลิงก์ใน `js/config.js`** ส่วน `REHOME`: `postFormUrl` = ลิงก์ฟอร์ม (viewform), `listingsCsvUrl` = ลิงก์ CSV จากขั้นที่ 5 แล้วเพิ่ม `CACHE_VERSION` ใน `sw.js`

ทุกวันให้เปิดชีตคำตอบ ตรวจโพสต์ใหม่ (รูปเหมาะสม ไม่ใช่การขาย ข้อมูลครบ) แล้วติ๊ก `อนุมัติ` โพสต์จะขึ้นแอปภายในไม่กี่นาที เมื่อมีคนแจ้งโพสต์ไม่เหมาะสม คำแจ้งจะเข้าฟอร์มความคิดเห็น (ประเภท `report`) ถ้าต้องการนำโพสต์ออก ให้เอาเครื่องหมายอนุมัติออก

## สมุดสุขภาพน้อง (แท็บ "โปรไฟล์")

เก็บข้อมูลน้องได้หลายตัว ทั้งหมดอยู่ใน `localStorage` ของเครื่องผู้ใช้เท่านั้น ไม่ต้องสมัครสมาชิก ไม่ส่งไปที่ไหน

- เลือกน้องจากแถวรูปด้านบน เพิ่ม/แก้ไข/ลบน้อง (ยืนยันในหน้า ไม่ใช้ป๊อปอัป)
- บันทึก **น้ำหนัก** (มีกราฟเมื่อมี 2 บันทึกขึ้นไป) **วัคซีน** และ **ถ่ายพยาธิ/ป้องกันเห็บหมัด** พร้อมวันนัดที่สัตวแพทย์แนะนำ แอปไม่คำนวณหรือแนะนำตารางวัคซีนหรือขนาดยาเอง
- "นัดที่ใกล้ถึง" แสดงนัดภายใน 30 วันและนัดที่เลยกำหนด หน้าแรกแสดงการ์ดเมื่อมีนัดภายใน 7 วันหรือเลยกำหนด ปุ่ม "เพิ่มลงปฏิทิน" ดาวน์โหลดไฟล์ `.ics` (เตือนล่วงหน้า 1 วัน) ไม่มี push notification เพราะต้องใช้เซิร์ฟเวอร์
- **ยา**: ชื่อยา วิธีให้/ขนาดเป็นข้อความอิสระตามที่สัตวแพทย์สั่ง (แอปไม่แนะนำยา ขนาด หรือความถี่เอง) เวลาให้ยา 1–6 เวลาต่อวัน วันเริ่ม/สิ้นสุด (ว่าง = ต่อเนื่อง) และวันรับยาครั้งถัดไป ยาที่ผ่านวันสิ้นสุดแล้วอยู่ใต้ "ยาที่หยุดแล้ว" การ์ด **"วันนี้ต้องให้ยา"** แสดงในสมุดและหน้าแรก กด "ให้แล้ว" เพื่อบันทึก (เวลาที่ผ่านไปแล้วขึ้น "เลยเวลา") "เพิ่มลงปฏิทิน" สร้าง `.ics` หนึ่งไฟล์ มีกิจกรรมซ้ำทุกวัน (`RRULE:FREQ=DAILY` ถึงวันสิ้นสุด หรือ 30 ครั้งถ้าให้ต่อเนื่อง) ต่อหนึ่งเวลา เตือนตรงเวลา และวันรับยาเป็นกิจกรรมทั้งวันเตือนล่วงหน้า 1 วัน วันรับยาแสดงใน "นัดที่ใกล้ถึง" ด้วย
- **นัดหมอ**: วันนัด (ใส่วันในอนาคตได้) เวลา คลินิก เรื่องที่นัด หมายเหตุ และ "ไปแล้ว" นัดที่ยังไม่ได้กด "ไปแล้ว" แสดงใน "นัดที่ใกล้ถึง" และหน้าแรก (ภายใน 7 วันหรือเลยวันนัด) `.ics` เป็นกิจกรรม 1 ชั่วโมงถ้ามีเวลา (เตือนก่อน 1 วันและ 2 ชั่วโมง) หรือทั้งวัน (เตือนก่อน 1 วัน) พร้อมสถานที่
- การเตือนในแอปทำงานเมื่อเปิดแอปเท่านั้น ถ้าต้องการให้มือถือเตือนให้ใช้ "เพิ่มลงปฏิทิน" (ไม่ใช้ Notification API)
- "สำรองข้อมูล" ดาวน์โหลด `kindaimai-backup-YYYY-MM-DD.json` และ "กู้คืนข้อมูล" ตรวจไฟล์อย่างเข้มงวดก่อนแทนที่ (ยืนยันในหน้า)
- ถ้าเบราว์เซอร์บันทึกข้อมูลไม่ได้ (เช่น โหมดส่วนตัวบางแบบ) แอปยังใช้งานได้ในหน่วยความจำและแสดงข้อความเตือน

**รูปแบบข้อมูล** คีย์ `kdm-pets-v1`:

```
{ activeId, pets: [ { id, name, species: 'dog'|'cat', birthDate: 'YYYY-MM-DD'|'',
    ageYears, ageMonths, ageSetAt,            // อายุโดยประมาณ + วันที่กรอก (อายุจะเพิ่มตามเวลา)
    sex: ''|'male'|'female', sterilized: ''|'yes'|'no', lifeStage: 'young'|'adult'|'senior',
    flags: { overweight, kidney },
    weights:  [ { id, date, kg } ],
    vaccines: [ { id, date, name, nextDue, note } ],
    deworm:   [ { id, date, product, nextDue, note } ],
    meds:     [ { id, name, instructions, times: ['08:00', ...], start, end, refillDate, note,
                  doses: [ { date, time, at } ] } ],   // doses เก็บย้อนหลัง 90 วัน
    appts:    [ { id, date, time, clinic, reason, note, done } ],
    createdAt } ] }
```
วันที่เก็บเป็น ISO ตามวันในเครื่อง (ไม่ใช่ UTC) และแสดงแบบไทย พ.ศ. อายุน้อยกว่า 12 เดือนจะเป็นช่วงวัย "ลูก" อัตโนมัติ และไม่แสดงตัวเลข kcal ของขนม

**การย้ายข้อมูลเดิม** ครั้งแรกที่เปิดเวอร์ชันนี้ ถ้ามีโปรไฟล์เดิม (`kdm-profile`: ชนิด น้ำหนัก ช่วงวัย น้ำหนักเกิน/โรคไต ชื่อ) แอปจะแปลงเป็นน้องตัวแรก (น้ำหนักเดิมเป็นบันทึกน้ำหนักวันนี้ ช่วงวัย "ลูก" เดิมเป็น `young`) แล้วลบคีย์เดิมหลังบันทึกคีย์ใหม่สำเร็จเท่านั้น ถ้าข้อมูลในคีย์ใหม่เสียหาย แอปเก็บสำเนาไว้ที่ `kdm-pets-v1-damaged` และเริ่มสมุดใหม่

## ข้อควรรู้

- Google Forms ไม่ส่งผลกลับมาให้แอปอ่าน แอปจึงรู้แค่ว่าส่งออกจากเครื่องแล้ว ไม่รู้ว่า Google รับสำเร็จหรือไม่ ควรตรวจใน Google Sheets เป็นระยะ
- การให้คะแนนหรือคำค้นที่ส่งตอนออฟไลน์จะไม่ถูกส่งซ้ำภายหลัง (มีสำเนาเก็บในเครื่องผู้ใช้ และแนบไปกับข้อความสรุปของแบบสอบถาม)
- ผู้ใช้ปิดการส่งข้อมูลอัตโนมัติได้ที่หน้า "เกี่ยวกับข้อมูล" > "ไม่ส่งข้อมูลการใช้งาน"
- ถ้าใช้ GitHub Pages แบบ `ชื่อผู้ใช้.github.io` (ไม่มีชื่อ repository ต่อท้าย) ปุ่ม "กลับหน้าแรก" ในหน้า 404 อาจพาไปผิดที่ ให้แก้สคริปต์ท้าย `404.html` เป็น `a.href = '/'`
